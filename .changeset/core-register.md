"@alxia/core": minor
---

`Register`: an app augments it once with the chain that builds its context, `declare module '@alxia/core' { interface Register { context: typeof base } }`, and a file that imports `@alxia/core` reads that context with no import of the app. `AppContext` is that context (`BaseContext` when nothing is registered), for a service or a resolver. `defineRoutes(prefix?)` is `alxia({ prefix })` typed with it, and carries it as a requirement through every route, `derive` and `use` declared on it, which `use(routes)`, `use(() => routes)` and a `group` returning it check: `base.use(defineRoutes('/todos').get('/', ({ user, reply }) => …))` compiles, `alxia().use(todos)` does not. Register the base, not the app that mounts the routes, which would be typed by itself (TS7022); a `context` that is not an app reads as `InvalidRegister`, and two registrations conflict (TS2717). `defineMiddleware(fn)` still reads `BaseContext`; `defineMiddleware<AppContext>()(fn)` requires the registered context where it is given. New types: `Register`, `AppContext`, `RegisteredOf`, `RegisteredBase`, `InvalidRegister`, `RoutesContext`, `RequiringContext`, `RequiredIn`, `Mounted`.
