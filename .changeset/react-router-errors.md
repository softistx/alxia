'@alxia/react-router': minor
---

Add `@alxia/react-router/errors`, the code with no UI that words an API's refusals for the page. It declares the shape of a GraphQL API's refusal structurally, so the subpath needs no `@nxgt/graphql-client` at runtime and never imports `@alxia/core`; its only runtime import is `react-router`, and `react` (an optional peer) is imported for types only.

- **The API's error.** `ApiErrorLike` (with `ApiErrorEntryLike`, `ApiErrorExtensionsLike`, `ApiFieldErrorLike`), `isApiErrorLike` (like the client's `isApiError`, plus a numeric `status`; it holds across two copies of the client) and `waitMinutes` (the minutes of a throttle's wait). `REQUEST_ID_HEADER` and `requestIdOf(response)` give the id an API echoes on a response, `nextOf(url)` the page a request is for (the `next` that carries it back after sign-in), and `FormErrors` what a form action answers when the API refused the input.
- **The API's words.** `createApiMessages({ format })` holds the API's message catalogue as an instance, where the app injects its ICU formatter (a `DATE` argument is a calendar day in every time zone). `apiCodeResolver(messages, { translate, language })` is the `{ translate, codeOf }` a form's `useCodeResolver` takes: it words a refinement's API code as the API does and never shows the code. `ApiMessagesProvider` fills the store in the browser from the root's data and writes nothing during a server render.
- **A refusal, worded.** `createApiErrors({ messages, unavailable })` returns `apiErrorMessage`, `fieldErrors`, `translateCode`, `unavailableMessage` and `apiRefusal` (an `ApiRefusal`, `{ message, status }`), with `refused` for the generic refusal of an error with no API code and `byCode` for the codes an app words itself.
- **Answering with it.** `routeError(error, { statuses?, requestIdHeader? })` is what a loader throws for the API's error: a 401, 403, 404 or 503 `ApiError`, or such a `Response` carrying an `x-request-id`, becomes a route error of that status with its `code`, `message` and `requestId`, and any other `ApiError` with an id becomes a 500 carrying it. `errorRequestId(error)` is the support reference an error page shows. On `createApiErrors`'s result, `fetcherResult(language, about, run)` is a fetcher's action (`{ ok: true }` with the value, or `{ ok: false, error }`), `fetcherRefusal(error, language)` its refusal, and `submitForm(language, run, fieldOf)` a form's action, the refusal placed under the form's fields as a `FormErrors`.
- **JSON actions.** `jsonActions({ origin? })` returns `readJson(request)` (JSON only, and only from this site: 403 `Cross-site request refused`, 415 `Expected a JSON body`, 400 `Malformed JSON body`; `origin` is a string or a getter, for an app behind a TLS-terminating proxy), `requireJsonPost(request)` (a native post goes back to its page) and `readInput(request, schema)` (the body's `input` through a Standard Schema, whose async validation is awaited; 400 `The form sent an input the API would refuse`). `useJsonFetcher(key?, action?)` is the fetcher that posts that JSON (`{ fetcher, post(body, to?), busy }`, with `JsonBody`). The Standard Schema v1 types are declared in the subpath (`StandardSchemaV1`, type only).
- **A fresh catalogue.** `createErrorCatalogue({ messages, languages, read, versions, ttlMs, clientCodes, retryMs?, firstReadWaitMs?, log? })` returns `fresh(language, now?)`, `freshAll(now?)`, `warm()`, `clientMessages()`, `reset()`, `heldVersion(language)` and `settled()`. A language with no catalogue yet is awaited for at most `firstReadWaitMs` (1500 ms), read once however many requests ask, and retried `retryMs` (5000 ms) after a failure; a held one is served as it is and its version is checked in the background once per `ttlMs` (a number or a getter), re-reading only the languages whose version moved. The root's middleware awaits `freshAll()`, its loader returns `clientMessages()` and `server.ts` calls `warm()`. An empty `languages` throws a `TypeError`.
- **A failed call.** `apiCallFailure(error, { api, operation?, requestId?, signal?, passedThrough?, log? })` returns what a loader or an action throws and logs it with the request id: an `ApiError` as it is (with `requestId`), a `Response` of its own status for a 401, 403 or 404 without a GraphQL body, a 503 `Response` for an unreachable, slow, garbled or aborted API, and any other error as it is. It recognises `@nxgt/graphql-client`'s `ApiStatusError` and `ApiUnavailableError` by `name` rather than `instanceof`, and a `passedThrough` status that cannot carry a body (101, 204, 205, 304) is answered with an empty one. `operationName(document)` names the operation for the log, over a structural `{ definitions }` so `graphql` is not imported. The call itself, its headers and its caller stay the app's.
