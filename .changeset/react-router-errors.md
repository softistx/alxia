'@alxia/react-router': minor
---

Add `@alxia/react-router/errors`, the code with no UI that words an API's refusals for the page. Its first slice holds the shape of a GraphQL API's refusal, declared structurally so the subpath needs no `@nxgt/graphql-client` at runtime: `ApiErrorLike` (and `ApiErrorEntryLike`, `ApiErrorExtensionsLike`, `ApiFieldErrorLike`), `isApiErrorLike` (like the client's `isApiError`, plus a numeric `status`, which `ApiErrorLike` promises; it holds across two copies of the client) and `waitMinutes` (the minutes of a throttle's wait); `REQUEST_ID_HEADER` and `requestIdOf(response)`, the id an API echoes on a response; `nextOf(url)`, the page a request is for without React Router's single-fetch details, for the `next` that carries it back after sign-in; and `FormErrors`, what a form action answers when the API refused the input. The subpath imports nothing at runtime, and never `@alxia/core`. Its second slice words the page's own forms in the API's words: `createApiMessages({ format })`, a catalogue store held as an instance (with `ApiMessages`, `CatalogueMessage(s)`, `ParamKind`, `MessageFormat`), where the app injects its ICU formatter, such as `@nxgt/material`'s `formatMessage`, and a `DATE` argument is a calendar day in every time zone; `apiCodeResolver(messages, { translate, language })`, the `{ translate, codeOf }` a form's `useCodeResolver` takes, which words a refinement's API code as the API does and never shows the code; and `ApiMessagesProvider`, which fills the store in the browser from the root's data and writes nothing during a server render, a plain function with no JSX that imports React for its types only (`react` is an optional peer). Its third slice words a refusal: `createApiErrors({ messages, unavailable })` returns `apiErrorMessage`, `fieldErrors`, `translateCode`, `unavailableMessage` and `apiRefusal` (an `ApiRefusal`, `{ message, status }`), with `refused` for the generic refusal of an error with no API code and `byCode` for the codes an app words itself, such as a query's limits. Its fourth slice answers with it: `routeError(error, { statuses?, requestIdHeader? })`, what a loader throws for the API's error (a 401, 403, 404 or 503 `ApiError`, or such a `Response` carrying an `x-request-id`, becomes a route error of that status with the `code`, `message` and `requestId`; any other `ApiError` with an id becomes a 500 carrying it), `errorRequestId(error)` (the support reference an error page shows) and `RouteErrorData`; and, on `createApiErrors`'s result, `fetcherResult(language, about, run)` (a fetcher's action: `{ ok: true }` with the value, or `{ ok: false, error }` with the refusal's status), `fetcherRefusal(error, language)` and `submitForm(language, run, fieldOf)` (a form's action: the refusal placed under the form's fields as a `FormErrors`). `FormErrors`' `formError` now accepts `undefined`. The subpath's one runtime import becomes `react-router` (`data`). Its fifth slice adds the JSON actions: `jsonActions({ origin? })` returns `readJson(request)` (JSON only, and only from this site: 403 `Cross-site request refused` for another `Origin` or a cross-site `Sec-Fetch-Site`, 415 `Expected a JSON body`, 400 `Malformed JSON body`; `origin` is a string or a getter, for an app behind a TLS-terminating proxy), `requireJsonPost(request)` (a native post goes back to its page) and `readInput(request, schema)` (the body's `input` through a Standard Schema, whose async validation is awaited; 400 `The form sent an input the API would refuse`); and `useJsonFetcher(key?, action?)`, the fetcher that posts that JSON (`{ fetcher, post(body, to?), busy }`, with `JsonBody`). The Standard Schema v1 types are declared in `/errors` (`StandardSchemaV1`, `StandardResult`, `StandardIssue`, `InferOutput`, type only), so the subpath still names `@alxia/core` nowhere, and `react` stays a type-only import.
