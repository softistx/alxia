'@alxia/react-router': minor

Add `@alxia/react-router/errors`, the code with no UI that words an API's refusals for the page. Its first slice holds the shape of a GraphQL API's refusal, declared structurally so the subpath needs no `@nxgt/graphql-client` at runtime: `ApiErrorLike` (and `ApiErrorEntryLike`, `ApiErrorExtensionsLike`, `ApiFieldErrorLike`), `isApiErrorLike` (like the client's `isApiError`, plus a numeric `status`, which `ApiErrorLike` promises; it holds across two copies of the client) and `waitMinutes` (the minutes of a throttle's wait); `REQUEST_ID_HEADER` and `requestIdOf(response)`, the id an API echoes on a response; `nextOf(url)`, the page a request is for without React Router's single-fetch details, for the `next` that carries it back after sign-in; and `FormErrors`, what a form action answers when the API refused the input. The subpath imports nothing at runtime, and never `@alxia/core`. Its second slice words the page's own forms in the API's words: `createApiMessages({ format })`, a catalogue store held as an instance (with `ApiMessages`, `CatalogueMessage(s)`, `ParamKind`, `MessageFormat`), where the app injects its ICU formatter, such as `@nxgt/material`'s `formatMessage`, and a `DATE` argument is a calendar day in every time zone; `apiCodeResolver(messages, { translate, language })`, the `{ translate, codeOf }` a form's `useCodeResolver` takes, which words a refinement's API code as the API does and never shows the code; and `ApiMessagesProvider`, which fills the store in the browser from the root's data and writes nothing during a server render, a plain function with no JSX that imports React for its types only (`react` is an optional peer).
